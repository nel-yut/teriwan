## 2. 世界観・ストーリー

### 2.1 舞台
城塞都市**ルーメル**。中央に古い遺構「星渡りの門」があり、世界各地の断片的な景色を映す8つの門へ通じる。人々はモンスターを**幻獣**と呼び、相棒として共存する。門を越えるには調律された「星印」が必要。毎年開かれる**星冠杯**は、門を安全に調査できる最高位の幻獣使いを選ぶ大会。

### 2.3 シナリオ全体（5幕）
1. **序章・小さな門**：主人公はルーメルに到着。最初の幻獣を受け取り「芽吹きの門」へ。帰還後、星冠杯予選の存在を知る。
2. **第一幕・不揃いな星印**：門2～3を攻略、予選C/B級に相当する大会を突破。門の最奥で星印の欠けを発見。ライバルと競う。
3. **第二幕・門のささやき**：門4～6の異変を調査。幻獣が暴走する原因は「星印の同期ずれ」と判明。ノクティスは門の閉鎖を主張。
4. **第三幕・星冠への道**：門7～8を攻略し、8つの調律核を回収。門を閉じるのではなく共鳴を安定化できると知る。大会準決勝へ。
5. **終章・星冠杯**：ライバル、前王者エラと対戦。優勝と同時に調律核が共鳴し、門が安定化。街の祝賀会、スタッフロール。以後自由行動。

### 2.4 進行状態とイベント
- `storyFlags` は `introDone`, `gate01Clear` ～ `gate08Clear`, `tournamentRank`（0～5）, `breedingUnlocked`, `endingSeen`, `gateAnomalyResolved`。
- 遷移は **フラグ条件表** で管理。直接UIイベントにストーリー条件を埋め込まない。
- 1門のクリアは各最終階ボス討伐＋帰還のイベント処理で確定。
- 詰み防止: 全パーティ全滅時は街へ帰還。セーブは保持。初期モンスターを失っても無料の再加入手段を確保する。
- 分岐エンディングなし。プレイヤーの選択でメイン進行不能にならない。

## 3. ゲームループ

`ルーメルで編成・買物・預かり・配合 → 開放済みの門へ → 自動生成階層を探索 → 戦闘・仲間加入・宝箱 → ボス撃破/帰還 → 育成・配合 → 大会挑戦 → 次の門解放`。

### 3.1 拠点の機能
- 中央広場: ナビ・進行通知・会話。
- 門の間: 8門の選択、解放条件・推奨Lv・探索記録。
- 幻獣牧舎: パーティ3体、控え枠、預かり・入替・解放。
- 配合堂: 血統と相手、結果プレビュー、継承確認、不可逆確定。
- 孵化所: 卵の預かり・孵化（時間経過ではなく戦闘経験値蓄積で進む）。
- 道具屋: 回復・肉・帰還など、ゴールドで購入。
- 星冠競技場: ランク別の連戦と報酬。
- 記録庫: 図鑑、配合の既知情報、セーブ管理。

### 3.2 大会（本作設計）
| ランク | 必要条件 | 対戦数 | 推奨Lv | 勝利報酬/解禁 |
|---|---|---:|---:|---|
| 見習い | 序章終了 | 2 | 5 | 門2、道具追加 |
| 青銅 | 門2クリア | 3 | 12 | 配合、門3・4 |
| 白銀 | 門4クリア | 3 | 20 | 門5・6、装備ではなく育成報酬 |
| 黄金 | 門6クリア | 3 | 28 | 門7・8 |
| 星冠杯 | 門8クリア | 4 | 35～42 | エンディング |

- 大会は連戦・各戦後の任意の全快なし（大会前の持込み道具は制限）。
- 負けた場合は大会開始地点へ戻り再挑戦可。失われるものは参加費のみ（初回・最終大会は無料）。
- 対戦相手は大会ごとに固定パーティと作戦を持つ。試合中の強制仲間加入なし。

### 4.1 階層生成
- 32×32タイルを最大領域とし、実使用24×24程度（調整値）。シード付き乱数 `rng(seed)` をゲーム全体で使用。
- 各階を独立生成。ボス階は固定レイアウト、雑魚階はランダム。
- 生成法: 矩形部屋6～10を非重複配置→通路で全連結→出口/入口を到達距離の長い2点に置く→宝箱/障害物/敵を配置。
- **必須不変条件**: 入口から出口へ徒歩で到達できる。仕掛けで出口が恒久封鎖されない。行き止まりから詰まない。
- 探索画面はタイル座標のプレイヤー移動、4方向移動、歩行アニメーション。縦持ちスマホでは仮想十字キー。端末横持ち/PCでは矢印キー・WASD。
- エンカウントは歩数カウンタ＋確率（基準平均12～20歩、門で調整）。安全地帯や階段1歩目では発生しない。マップ内に見える敵は初期実装ではなし。
- 出口階段に入ったら次階層へ。最終階はイベント・ボス戦後に帰還。途中帰還アイテムあり。
- 宝箱位置・中身・ランダム生成状態はフロア再入場時に更新、同一セッション内は安定。
- 再開時のランダム生成の一貫性のためフロアシード、訪問済み宝箱、プレイヤー位置、歩数を保存する。

### 4.2 門別イベント
- 芽吹き: 子どもの幻獣が木の根に閉じ込められている。救出でボス出現。
- 風鈴: 風の音が鳴らない塔。風床を使って鐘に到達。
- 潮騒: 水位の変化。橋を順に架ける。
- 鉄屑: 停止した機械を再起動。回転床を解除。
- 炎脈: 熱源の暴走を鎮める。耐熱通路へ誘導。
- 白凪: 氷結した星印を解凍。足元の滑りに注意。
- 朧影: 偽物の扉を見抜く。ノクティスとの対話。
- 星環: 8つの調律核を揃え、始原竜の試練を越える。

## 5. モンスター設計

### 5.1 基本構造
- 10系統×各10種=100種。各系統は序盤3、中盤4、後半2、頂点1の強さの階段。
- 固有成長: HP/MP/攻撃/守備/素早さ/賢さ（賢さはAI行動の参照に利用）。各能力は0～999（HPは1～999）。これは **本作設計の調整値**。
- `gender`: `M`/`F`。捕獲時は等確率を初期値。性別変更アイテムなし。
- `plus`: 配合回数・両親の育成情報から生成される加算値、上限99（本作調整値）。
- `personality`: `brave`, `careful`, `gentle`, `wild`。AI作戦時の選好に作用（本作設計）。
- 1体ごとに固有UUIDを持つ。種族IDとは異なる。
- 種族図鑑は遭遇・仲間・配合既知・倒した数を別々に記録。

## 6. 戦闘詳細

### 6.1 フェーズと状態遷移
`START → COMMAND → ACTION_QUEUE → RESOLVE → TURN_END → VICTORY / DEFEAT / ESCAPE / NEXT_TURN`。
- 3体までの味方・最大3体の敵（ボス例外でも最大3）。前衛後衛・陣形なし。
- 各ターン、個別作戦（ガンガン/バッチリ/いのち/めいれい）または全体指示を設定。作戦時はAIが行動選択。
- プレイヤー入力の「たたかう」「とくぎ」「どうぐ」「にげる」を備える。命令可能かどうかは作戦状態に依存。
- 行動順は `agility + RNG(0..floor(agility*0.2))` の降順（**本作暫定式**）。同点時はバトル開始順に固定。
- 戦闘不能・眠り・麻痺・混乱・毒・沈黙・防御上昇/低下・攻撃上昇/低下・状態解除をサポート。
- HP=0なら戦闘不能。戦闘不能中は行動不可。味方全滅で敗北。
- 戦闘勝利時、経験値・G・ドロップ・加入判定を順番に処理。

### 6.2 ダメージとコマンド（調整値）
- 通常攻撃: `max(1, floor(ATK/2 - DEF/4) + variance)`、`variance = floor(base*U[-0.1,+0.1])`。ダメージ上下限0～999。防御時0.5倍。クリティカル基準1/32、ダメージ1.5倍。
- 呪文威力: `basePower + floor(INT*scale)` と耐性倍率・ゆらぎを適用。
- 回復: `baseHeal + floor(INT*scale)`、最大HPを超えない。
- `escape` 成否は素早さ比率と試行回数に基づくテーブル。ボス・大会は逃走不可。
- 戦闘中アイテム消費は効果処理と同一トランザクション。対象不在/選択キャンセル時には消費しない。

### 6.3 AI作戦
| 作戦 | 評価関数の重点 | 禁止条件 |
|---|---|---|
| ガンガンいこうぜ | 期待ダメージ最大、MP消費を許容 | MP不足の特技 |
| バッチリがんばれ | 攻撃・補助・回復の総合期待値 | 対象なしの補助 |
| いのちだいじに | 生存率、回復、状態異常治療 | 不要な回復 |
| めいれいさせろ | 手動コマンド指定 | 指定不能/戦闘不能 |

### 6.4 勝利・仲間加入
- 野生戦闘に勝利し、かつ対象が加入可能であるとき確率判定。仲間加入判定は敵パーティから最大1体。
- 各種族 `recruitBase`（E .18 / D .12 / C .07 / B .035 / A .015 / S 0）を初期値とし、投入肉の倍率を乗算し上限0.8（本作調整値）。同じ戦闘で複数肉を使った場合は肉効果を加算し上限処理。
- 牧舎に空きがない場合は加入ダイアログから入替/拒否を選択。無言破棄はしない。
- ボスは初回戦闘では原則仲間にならず、ボスと同種のモンスターが配合で入手可能。
- 経験値は生存/戦闘不能にかかわらず参加した味方に付与するかを **調整パラメータ** にして初期値は生存のみ。厳密なGB挙動は要検証。

## 7. 配合・孵化詳細

### 7.1 前提・操作
- 青銅ランク優勝後に解放。血統（ベース）と相手（パートナー）を1体ずつ指定。
- 互いに別個体、♂♀異性、両親ともLv10以上。戦闘中/ダンジョン中は配合不可。
- 子の種類と継承候補を確認した後、「両親は戻らない」を明示した最終確認を行う。
- 配合結果は卵（種族・継承情報・性別は配合確定時に決定）。親2体を削除し、卵を登録。個別の取消不可。
- 孵化は獲得経験値累計が閾値（例:100、調整値）に達したら可能。未孵化卵は牧舎の上限から別管理。卵所持上限20。
- 子はLv1、経験値0、両親の継承可能特技の候補を保持。孵化後の性別は50:50で初期化（性別は卵の生成時に決め保存）。

### 7.2 種族決定優先順位
1. **特定種族×特定種族の特別配合**（血統方向を区別、同条件で高優先度を優先）。
2. **血統種族×相手系統の指定配合**。
3. **血統系統×相手系統の通常配合**。
4. **既定フォールバック**: 血統系統内の種族のうち、親血統の「段階」や相手ランクで決まる種族。

- `resolveBreeding(bloodline,partner)` は純粋関数。**任意の異性種族ペアに対して必ず結果を返す**。
- 原則、通常配合では血統の系統を継承。特別配合では例外を許す。
- 血統/相手を入替えると結果が変わり得る（性別や前提条件は同じ）。

### 7.3 通常配合の完全決定規則（100種全組合せを網羅）
系統順は `芽精,獣牙,羽翼,鱗甲,鉱機,幽影,火霊,氷晶,星妖,古竜`（index 0～9）。各系統の10種は図鑑表の先頭からindex 0～9。
- 相手系統index = `p`、血統系統index = `b`、血統種のindex = `i`、相手のindex = `j`。
- 子の通常配合index = `min(8, max(0, floor((i+j)/2) + (p%3) - 1))`。
- 子は血統系統の上記index種。**通常配合だけでは各系統のS種（index9）にはならない**。
- この式は本作独自の暫定フォールバックであり、GB版の配合表ではない。特別配合テーブルが優先。
- フォールバックは全順序対をカバーするので「組み合わせ不明」状態を作らない。

### 7.4 特別配合レシピ（必須）
- 各系統のindex8（A級）×同系統のindex8（A級） → 同系統index9（S級）。血統と相手は異性・別個体であること。
- 追加のクロス系統特殊配合（いずれも血統指定）：
  - `M010 × M090 → M100`（樹冠王ユグラ×星詠ミラ→始原竜エルド）
  - `M020 × M080 → M090`（白銀獣ヴァルガ×氷妃ネーヴェ→星詠ミラ）
  - `M030 × M070 → M080`（天翔鳥セレス×太陽霊ソル→氷妃ネーヴェ）
  - `M040 × M060 → M070`（碧甲竜オルム×影王ノクス→太陽霊ソル）
  - `M050 × M030 → M060`（星鋼巨兵アスト×天翔鳥セレス→影王ノクス）
- これらはハイエンドの追加導線。上記S種同士のレシピとも併存し優先度はクロス特殊＞同系統A×A＞通常。
- 重要: 種族の再帰入手性をテスト。S種の親であるA種は通常配合で到達可能。

### 7.5 継承
- 初期能力値は子の種族基礎値に `floor((parentA.stat + parentB.stat)/20)` を加算（HP/MP含む）。上限でクリップ（**本作暫定式**）。
- `plus = min(99, floor((pA.plus+pB.plus)/2)+1)`（**本作暫定式**）。
- 習得候補は子固有最大3技＋両親が使用可能だった技の和集合。重複排除、順序固定、最大保持候補16。
- 戦闘で使用できる**習得済みスロット上限8**。新規習得時に8枠なら置換選択。候補を「習得済み」と混同しない。
- 継承候補技も習得必要Lv/能力値を満たしたときに使用可能になる。親の強力技がLv1から無条件で使用可能にならない。
- 親の個体UUID・種族・plusは系譜に記録。親そのものは削除。
- 配合ロジックは保存更新前にプレビューと確定結果の一致を保証し、確定時にはスナップショット保存。

- モンスター立ち絵: 透過PNG/WebP、正面からやや3/4、明瞭なシルエット、過度な細部なし、同一の光源。キャラ全身が切れない構図。
- 人物立ち絵: 3/4身、表情差分（通常/喜/困惑/決意）、衣装・色指定をキャラマスターに保持。
- 探索タイル: 32または48px基準で統一、床/壁/階段/宝箱/トラップのオートタイル、継ぎ目の検査。
- UI: 深紺と薄金、空と星の意匠。重要文字は背景との十分なコントラスト。
- AI生成結果の権利・利用条件・類似性を検査し、既存ゲームのキャラクター再現を指定しない。
- BGM/SEは本書では音源未制作。オフライン再生できる独自音源または適切な利用許諾のある素材のみ使用。

## 11. 技術アーキテクチャ

### 11.1 推奨スタック（本作設計）
- TypeScript、Vite、React（施設画面/設定/リスト）、PixiJS（タイル探索/戦闘エフェクト）。
- Zustand等の軽量ストアでUI状態、コアロジックは依存のない純粋TypeScriptモジュール。
- IndexedDB（`idb`等）にセーブデータ、LocalStorageは音量や短いUI設定のみ。
- PWA: Service Worker＋アセットプレキャッシュ、オフラインフォールバック。WebアプリはHTTPSまたはlocalhostで導入。
- シングルプレイのためバックエンド無し。Web Workerは必要な場合のみマップ生成等に適用。

### 11.2 層と依存
- `domain/`: Monster, Party, Skill, Battle, Breeding, Dungeon, Progression の型と純粋関数。
- `data/`: monsters, skills, items, breedingSpecial, gates, tournaments, story を厳密スキーマで管理。
- `application/`: ユースケースと状態遷移、コマンド、イベントハンドラ。
- `infrastructure/`: IndexedDB/PWA/アセット/RNGシード。
- `presentation/`: React画面、PixiJS表示、入力。
- `tests/`: 純粋関数の単体テスト、全配合組合せ、データ整合、E2E。

### 11.3 主要型例（仕様用の疑似TypeScript）
```ts
type StatKey = 'hp'|'mp'|'atk'|'def'|'agi'|'int';
type Gender = 'M'|'F';
type FamilyId = 'sprout'|'beast'|'wing'|'scale'|'metal'|'shade'|'flame'|'frost'|'astral'|'dragon';
type BattlePhase = 'command'|'action'|'turnEnd'|'victory'|'defeat'|'escape';
interface MonsterSpecies {
  id: string; family: FamilyId; name: string; rank: 'E'|'D'|'C'|'B'|'A'|'S';
  baseStats: Record<StatKey,number>; growthWeights: Record<StatKey,number>;
  resistances: Record<string,0|0.5|1|1.5>; nativeSkillIds: string[];
  recruitBase: number; assetKey: string;
}
interface MonsterInstance {
  uuid: string; speciesId: string; nickname?: string; gender: Gender;
  level: number; exp: number; plus: number;
  stats: Record<StatKey,number>; currentHp: number; currentMp: number;
  knownSkillIds: string[]; inheritedSkillCandidates: string[];
```

### 11.4 セーブ整合性
- `schemaVersion` は整数で開始1。読込時のマイグレーション関数を実装。
- 保存単位は**ゲーム状態全体の整合したスナップショット**。IndexedDB単一readwriteトランザクション。
- 自動保存: 拠点帰還・戦闘終了・配合確定・大会終了・階層遷移時。手動保存: 拠点/探索メニューから可能。
- 保存スロットは3つ、各スロットは同時に開かず1つをアクティブにする。破損検知（ハッシュ/スキーマバリデーション）と直前バックアップ1世代。
- JSONセーブのエクスポート/インポートを用意。取込時バージョン検証・バックアップ・警告表示。
- ブラウザデータ削除・プライベートモード・端末変更ではローカルセーブが消え得ると初回説明。
- オフライン更新は**保存に影響しないアセット更新**に限定し、スキーマ変更はマイグレーション試験後に適用。

### 11.5 再現可能な乱数
- 全結果の乱数はゲームコアが供給するseed付きPRNGで生成。UI表示や再描画で乱数消費しない。
- 同一seed＋同一入力コマンド列→同一マップ・戦闘・配合性別・加入結果を要求。
- セーブ復旧後、次の乱数結果が異ならないようPRNG状態保存。

## 12. コンテンツバランス・進行設計

- 期待攻略時間: 序章1～2h、第一幕3～5h、第二幕5～7h、第三幕4～6h、終章2～5h = 合計15～25hを目標（重複調整が必要な見積り）。
- ボスは各門の主要系統の強みを活かす。単純なHP増加だけに頼らない。特技・耐性・回復・補助を適切に分散。
- 育成の主要導線を `野生で仲間集め→レベル10→配合→新種で門攻略` とする。序盤は配合不可でも進行できる。
- モンスター種族収集100%は最終大会のクリア条件に**しない**。終盤S種はクリア後も配合で回収可能。
- ドロップ/加入の確率・経験値量はログに表示せず、調整テーブルから更新可とする。

## 13. イベント・ゲームデータの検証ルール

1. モンスターIDはM001～M100重複なし、系統10×10、登録名非空。
2. すべての特技・アイテム・ボス・門・大会の参照IDが存在する。
3. 100×100の**種族の順序つき配合全組合せ**をテスト（両親異性の実行可能性とは別の純粋関数テスト）。返り値はM001～M100。
4. 10系統のS種（index9）について到達可能レシピがあり、必要なA種も到達可能。
5. 1～8門の全フロアを100 seed以上生成し、階段が到達可能、壁に埋まらない、ボス階が生成可能。
6. 「初期パーティ→全門→最終大会優勝」への進行フラグ経路が存在し、無限待ちイベントがない。
7. 継承候補と習得済技を区別し、8枠超過、参照失敗、同一個体を両親にする配合が発生しない。
8. 全データをZod等で起動時検証。検証失敗時は「壊れたセーブを上書きしない」。
9. スマホ縦持ちで常時操作可能、ソフトウェアキーボード出現時にボタンが隠れない。
10. ネットワーク遮断後、再ロード→プレイ→セーブ→再ロードできる。

## 付録: 実装との差分メモ(実装時に確定した事項)

設計書の方針を保ったまま、実装時に次のように確定・調整した。

### 技術スタック
- UI は React / PixiJS ではなく **素の TypeScript + DOM + Canvas** にした(依存を最小にしオフライン配布を単純にするため)。ロジックは `domain/` に分離済みなので、後から UI 層だけ差し替え可能。
- 検証は Zod、保存は `idb`(IndexedDB)、テストは Vitest。

### データ・仕様の確定
- **A ランク(index 8)は配合専用**とし、野生出現と加入率を外した(§5.3 の A 行の野生Lv域・加入率は無効)。S も同様。
- B ランクの野生個体は各門の最終階手前だけに低確率で出現する。
- 通常配合の式(§7.3)、特別配合(§7.4)は設計書どおり。`resolveBreeding` はテストで 100×100 全組合せを検証している。
- 加入率: `min(0.8, recruitBase × (1 + 肉ボーナス合計 × 6))`(肉の「+0.10」は倍率の加算として解釈)。
- 物理ダメージの基礎値は `ATK×0.8 − DEF×0.25`(設計書の `ATK/2 − DEF/4` だと序盤が 1 ダメージ固定になるため)。呪文・ブレスは威力に係数 0.6 を掛ける(HP テンプレートに対し威力が高すぎたため)。
- HP 成長は他能力の 2.2 倍換算(`monster.ts` の `STAT_SCALE`)。
- 経験値は敵 1 体につき `expToNext(敵Lv, ランク) × 0.12/(1+敵Lv/15) + 6`、レベル差で 0.5〜2 倍。1 レベル上げるのに必要な戦闘数の目安は Lv3 で約4戦、Lv20 で約7戦、Lv40 で約10戦(`tests/pace.test.ts` で確認)。
- 大会の試合間は HP/MP を最大の 40% 回復(全快はしない)。序盤の試合は下位ランクのみ、最終戦で上位ランクが混ざる。対戦相手の Lv は推奨 Lv −3 + 試合番号(星冠杯のみ推奨 Lv 基準)。
- 作戦(ガンガン/バッチリ/いのち/めいれい)は**パーティ全体で 1 つ**。個別指定は「めいれいさせろ」中のみ。
- 卵の孵化は戦闘勝利ごとの孵化ポイント(`8 + 獲得経験値×0.25`)が累計 100 に達すると可能(約8〜10戦)。

### グラフィック
- 当初の SVG 仮素材をやめ、**コード生成のドット絵**に変更。幻獣は 24×24(系統ごとの体型 + 色相/飾り/ランク演出)、マップタイルは 16×16(門ごとの配色と模様)。探索キャラは先頭の幻獣のドット絵で、歩行のはずみと左右反転がある。
- 種族 ID 名の PNG を `public/assets/monsters/` に置くと優先表示される(`manifest.json` で有効化)。

### 未実装(今後の拡張候補)
- 門ごとの特殊ギミック(風床・渡り板・歯車床・視界制限・ワープ床など)と、見えるシンボルエンカウント
- 状態異常のうち「混乱」「沈黙」を与える技(エンジンは対応済みだが現状の技に付与するものがない)
- 個体ごとの作戦指定、ブラウザの戻るボタンとの連動、振動設定
- AI 生成/手描きの本番素材・BGM(現状はコード生成のドット絵と WebAudio の簡易効果音。素材は `public/assets/` で差し替え可能)

### バランス検証
`tests/sim.test.ts` は AI の自動プレイでエンディングまで到達できることを確認する。終盤(白銀大会以降)は「配合で育てた精鋭チーム」を仮定して注入しており、配合ループそのものはユニットテストで別途検証している。実際の所要時間(15〜25 時間)は人によるプレイテストで調整が必要。
